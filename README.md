# xDaymohk (Даймохк)

Каталог жителей и специалистов Чеченской Республики (Даймохк/Самашки): анкеты,
отзывы, вопросы и ответы, рейтинги, карта с домами, расписание, уведомления,
админ-панель, рассылки писем.

**Стек:** Next.js 15 (App Router) · React 19 · TypeScript · Tailwind CSS 4 ·
Supabase (Postgres + Auth + Storage + Realtime) · Leaflet + markercluster ·
Upstash Redis (rate-limit) · Sentry (мониторинг, опционально).

---

## 🚀 Быстрый старт

```bash
npm install
npm run dev
```

Откройте http://localhost:3000.

Скопируйте `.env.example` в `.env.local` и заполните:

| Переменная | Обязательна | Что это |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | ✅ | URL вашего Supabase-проекта |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | ✅ | Публичный anon-ключ Supabase |
| `SUPABASE_SERVICE_ROLE_KEY` | ✅ (для админки/писем) | Секретный service-role ключ (только сервер!) |
| `DADATA_API_TOKEN` | опц. | DaData для подсказок адресов |
| `OSRM_ROUTER_URL` | опц. | OSRM-роутер для маршрутов (по умолчанию router.project-osrm.org) |

| `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN` | опц. | Rate-limit в serverless (иначе in-memory) |

> ⚠️ `SUPABASE_SERVICE_ROLE_KEY` — **никогда** не кладите в `NEXT_PUBLIC_*`

## 🤝 Темщик и Помощь

Единый движок заданий на два раздела, различаются флагом `is_paid`.

**Типы:** срочные (дедлайн «сделать до») и запланированные (дата + N мест,
запись участников).

**Цикл:** публикация → первый нажавший забирает → «Выполнил» →
подтверждение заказчиком. Если заказчик молчит **3 часа**, задание
закрывается само, а он получает блокировку на создание новых на **6 часов**.

**Требования к исполнителю** задаёт заказчик: минимальный рейтинг, возраст
аккаунта, число выполненных заданий, галочка «Показывать новичкам».
Проверяются на сервере, не в браузере.

**Рейтинг жителя** (`user_profiles.resident_rating`) — про человека как
участника сделок, отдельно от рейтинга специалиста (`profiles.rating`),
который про навыки. Оценка взаимная и только после завершённой сделки.

**Оплата договорная:** приложение фиксирует факт расчёта, деньги передаются
напрямую. Эскроу отложен — провайдеры безопасной сделки требуют оборот
от 800 тыс./мес. Поля `payment_status` и `escrow_deal_id` заложены заранее.

**Ограничения:** оплачиваемые задания с 14 лет (в ГIончалла возраста нет),
не больше 5 активных заданий на исполнителя, стоп-лист запрещённых
категорий при публикации.

**Обслуживание:** `19-tasks-cron.sql` (pg_cron каждые 5 минут) —
автоподтверждение, просрочка, напоминания за 2 часа. Роут
`/api/tasks/maintenance` дублирует его при открытии раздела.

## 🔐 Роли и права

- **Админы** (по email в `lib/admin.ts`): полный доступ к админке, бан, письма, адреса.
- **Пользователи**: свои анкеты, отзывы, вопросы, уведомления.
- **Блокировка**: `is_blocked` в `user_profiles` + `banned_until` (временный бан).
  Разблокировка админом → только личная анкета; истечение временного → все.

## 📨 Письма (рассылки)

Раздел «Письма» в админке:
- **Уведомление после регистрации** — письмо новому пользователю (2 языка);
- **Приветственное сообщение** — модальное окно при первом заходе (2 языка);
- **Написать письмо** — сразу всем/выбранным, или **по расписанию** (время, частота
  once/daily/n_days, сколько раз);
- **Архив** — очередь запланированных и «Отправленные» (история), редактирование
  карандашом и удаление корзиной;
- Автодоставка: **pg_cron в Supabase** (SQL-шаги 10–11, каждые 5 минут) + тихий
  запуск при открытии раздела «Письма»/«Архива» в админке (Vercel Cron не используется).

## 🛡️ Безопасность (что уже сделано)

- Rate-limit на всех API (Upstash Redis в проде, in-memory в dev);
- Единая аутентификация админов (`lib/auth.ts`);
- Service-role **только** на сервере (никогда на клиенте);
- RLS-политики на таблицах;
- Уникальный индекс адресов (защита от дублей на уровне БД);
- SSRF-защита `/api/route` (whitelist OSRM), валидация координат;
- Белый список языков в переводе;
- Security-заголовки (X-Content-Type-Options, X-Frame-Options и др.);
- **CSP** (`next.config.mjs`) — пока в режиме `Report-Only`;
- **HSTS** (`max-age` 2 года, `includeSubDomains`, без `preload`);
- Тесты критичных путей: админ-права, вебхук пожертвований, rate-limit;
- Sentry (опционально).

### Как включить CSP боевым режимом

Сейчас заголовок отдаётся как `Content-Security-Policy-Report-Only`:
браузер только пишет нарушения в консоль, но ничего не блокирует. Порядок:

1. Открыть сайт, пройти по разделам — особенно по карте, профилю с
   аватаром и странице с видео;
2. Посмотреть в консоли сообщения `Content Security Policy`;
3. Недостающие домены дописать в `cspDirectives` в `next.config.mjs`;
4. Когда консоль чистая — переименовать ключ заголовка в
   `Content-Security-Policy`.

Спешить с шагом 4 не нужно: в Report-Only политика уже даёт видимость,
но ничего не ломает.

## 🧪 Команды

```bash
npm run dev          # dev-сервер
npm run build        # продакшн-сборка
npm run typecheck    # проверка типов (tsc --noEmit)
npm run lint         # ESLint
npm run stylelint    # проверка CSS (ловит битый синтаксис)
npm run test         # тесты (vitest)
npm run verify       # всё сразу: типы, стили, линт, тесты, сборка
```

Перед пушем достаточно одной команды — `npm run verify`.

### Проверка перед коммитом

`husky` + `lint-staged` гоняют `stylelint` по CSS и `eslint` по TS на
каждом `git commit`. Хук ловит именно то, на чём проект однажды слёг, —
оборванное правило в CSS. Обойти можно через `--no-verify`, но тогда
сломанный файл уедет в репозиторий.
