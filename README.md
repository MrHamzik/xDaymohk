# xDaymohk (Даймохк)

Каталог жителей и специалистов Чеченской Республики (Даймохк/Самашки): анкеты,
отзывы, вопросы и ответы, рейтинги, карта с домами, расписание, уведомления,
админ-панель, рассылки писем.

**Стек:** Next.js 15 (App Router) · React 19 · TypeScript · Tailwind CSS 4 ·
Supabase (Postgres + Auth + Storage + Realtime) · Leaflet + markercluster ·
Upstash Redis (rate-limit) · Sentry (мониторинг, опционально).

---

## 🚀 Быстрый старт

```bash
npm install
npm run dev
```

Откройте http://localhost:3000.

### Переменные окружения

Скопируйте `.env.example` в `.env.local` и заполните:

| Переменная | Обязательна | Что это |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | ✅ | URL вашего Supabase-проекта |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | ✅ | Публичный anon-ключ Supabase |
| `SUPABASE_SERVICE_ROLE_KEY` | ✅ (для админки/писем) | Секретный service-role ключ (только сервер!) |
| `DADATA_API_TOKEN` | опц. | DaData для подсказок адресов |
| `OSRM_ROUTER_URL` | опц. | OSRM-роутер для маршрутов (по умолчанию router.project-osrm.org) |
| `CLOUDTIPS_WEBHOOK_SECRET` | опц. | Секрет вебхука CloudTips (пожертвования) |
| `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN` | опц. | Rate-limit в serverless (иначе in-memory) |
| `SENTRY_DSN` / `NEXT_PUBLIC_SENTRY_DSN` | опц. | Sentry-мониторинг |

> ⚠️ `SUPABASE_SERVICE_ROLE_KEY` — **никогда** не кладите в `NEXT_PUBLIC_*`
> и не импортируйте в клиентские компоненты.

## 🗄️ База данных (вручную, без CLI)

Никаких команд не нужно — **Supabase Dashboard → SQL Editor**, вставляете файл
целиком и жмёте Run.

### Новый проект (с нуля)

1. `supabase/schema.sql` — полная схема (идемпотентная, можно перезапускать).

### Обновление существующей БД (по шагам, по одному)

Применяйте **по одному** в порядке нумерации (чтобы не было конфликтов):

| Шаг | Файл | Что делает |
|---|---|---|
| 01 | `supabase/update/01-settlement.sql` | «Самашки» → «Даймохк» |
| 02 | `supabase/update/02-notifications-type.sql` | Типы уведомлений |
| 03 | `supabase/update/03-notifications-ce.sql` | Двуязычные уведомления (ce) |
| 04 | `supabase/update/04-notifications-delete-policy.sql` | Политика удаления уведомлений |
| 05 | `supabase/update/05-view-users-count.sql` | Счётчики пользователей |
| 06 | `supabase/update/06-work-days-nullable.sql` | `work_days` nullable |
| 07 | `supabase/update/07-clean-duplicate-addresses.sql` | Чистка дублей адресов |
| 08 | `supabase/update/08-storage-policies.sql` | Политики Storage (аватары `<uuid>.webp`) |
| 09 | `supabase/update/09-letters.sql` | Таблицы писем (`letters`, `letter_log`) |
| 10 | `supabase/update/10-letters-scheduler.sql` | Планировщик писем (очередь) |
| 11 | `supabase/update/11-pgcron-letters.sql` | Автодоставка писем (pg_cron) |
| 12 | `supabase/update/12-db-hardening.sql` | Уникальный индекс адресов + индексы |
| 13–17 | `supabase/update/13…17-*.sql` | Письма, приветствие, FK расписания, синхронизация пола/даты рождения |
| 18 | `supabase/update/18-tasks.sql` | **Аренца Темщик / ГIончалла**: задания, участники, рейтинг жителей, фильтры |

> 💡 **pg_cron (шаг 11)** — рекомендую включить: письма доставляются сами,
> без ручной кнопки.

### Storage

Bucket **`profile-media`** (public). Аватары: `avatars/<userId>.webp`
(перезаписываются). Документы: `documents/<userId>-<ts>.webp`.

## 🧭 Разделы приложения

| Раздел | Что это |
|---|---|
| **Главная `/`** | Каталог анкет: hero-баннер, поиск/фильтры, карточки специалистов |
| **Карта `/map`** | Leaflet-карта: слои «Анкеты / Дома / Другое» (переключатель), кластеры, фильтр категорий |
| **Профиль `/profile`** | Личный кабинет: аватар, анкеты, настройки |
| **Кибла** | Компас направления на Каабу (в боковом меню) |
| **Админка `/admin`** | Анкеты, жалобы, пользователи, адреса, **Письма** |
| **Такси `/taxi`** | Заказ поездки (в разработке) |

### Главная (домой)

- **Hero-баннер** — заголовок, подзаголовок, счётчики (анкет, рейтингов), кнопка «Открыть карту»;
- **Поиск и фильтры** (SearchFilter) — кто ищется (жители/специалисты/проверенные), сферы, статус работы;
- **Карточки анкет** (ProfileCard) — аватар, имя, бейджи (Специалист ⭐ / Проверен ✓ / Админ), профессия, рейтинг, кнопки;
- **Кнопка «Добавить анкету»** — для авторизованных.

## 🔐 Роли и права

- **Админы** (по email в `lib/admin.ts`): полный доступ к админке, бан, письма, адреса.
- **Пользователи**: свои анкеты, отзывы, вопросы, уведомления.
- **Блокировка**: `is_blocked` в `user_profiles` + `banned_until` (временный бан).
  Разблокировка админом → только личная анкета; истечение временного → все.

## 📨 Письма (рассылки)

Раздел «Письма» в админке:
- **Уведомление после регистрации** — письмо новому пользователю (2 языка);
- **Приветственное сообщение** — модальное окно при первом заходе (2 языка);
- **Написать письмо** — сразу всем/выбранным, или **по расписанию** (время, частота
  once/daily/n_days, сколько раз);
- **Архив** — очередь запланированных и «Отправленные» (история), редактирование
  карандашом и удаление корзиной;
- Автодоставка: **pg_cron в Supabase** (SQL-шаги 10–11, каждые 5 минут) + тихий
  запуск при открытии раздела «Письма»/«Архива» в админке (Vercel Cron не используется).

## 🛡️ Безопасность (что уже сделано)

- Rate-limit на всех API (Upstash Redis в проде, in-memory в dev);
- Единая аутентификация админов (`lib/auth.ts`);
- Service-role **только** на сервере (никогда на клиенте);
- RLS-политики на таблицах;
- Уникальный индекс адресов (защита от дублей на уровне БД);
- SSRF-защита `/api/route` (whitelist OSRM), валидация координат;
- Белый список языков в переводе;
- Security-заголовки (X-Content-Type-Options, X-Frame-Options и др.);
- Sentry (опционально).
