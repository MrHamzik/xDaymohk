## 3. Что нужно пометить в коде для прожектора (п.1)

Прожектор ищет элемент по атрибуту `data-tour`. Проставить в четырёх
местах:

| Метка | Файл |
|---|---|
| `data-tour="nav"` | `components/BottomNav.tsx` — панель целиком |
| `data-tour="catalog"`, `data-tour="map"` | `components/BottomNav.tsx` |
| `data-tour="menu"`, `data-tour="plus"` | `components/BottomNav.tsx` |
| `data-tour="widgets"` | `components/SettingsControlsBar.tsx` |

Поведение: гид затемняет экран, вырезает окно вокруг найденной кнопки,
обводит её и пульсирует. Если элемента нет на текущем экране (например,
на компьютере другая раскладка) — шаг показывается обычной карточкой,
без подсветки. Ломаться ничего не должно.

## Вопрос по п.12, требующий отдельного ответа

Вы выбрали «удалить столбец из базы». Предупреждаю прямо: `alter table
... drop column` **необратим**. После выполнения номера, записанные в
старых заданиях, исчезнут навсегда — восстановить их можно будет только
из резервной копии Supabase.

Безопасный порядок, который я предлагаю вместо одного удаления:

1. Сейчас — выкатить код: форма без «Общего номера», три тумблера,
   номера берутся из профиля. Столбец остаётся, его никто не читает.
2. Через неделю-другую, убедившись, что всё работает, — выполнить
   отдельную миграцию с `drop column`.

Так вы получите чистую базу без риска потерять данные в тот же день.
Скажите, делать так или всё же удалять столбец сразу.
